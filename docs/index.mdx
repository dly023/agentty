Agentty is a terminal-first agent workbench derived from tty7. Machines appear
together in the sidebar, with their session tabs underneath. The technical core,
CLI, server and configuration paths retain the `tty7` name.

Ordinary Quit closes the GUI while its background server can keep shells and
agents running. Reopening can reattach to surviving processes. Rebooting the
machine that owns a process ends that process: retained tabs, saved output and
provider history support recovery, not uninterrupted execution. **Rejoin**
attaches to a verified live session; **Resume** explicitly starts a supported
historical conversation. [Lifecycle details →](/agents/sessions)

It is written in Rust, renders on the GPU through Zed's
[gpui](https://github.com/zed-industries/zed), and parses VT with Alacritty's
terminal core. The inherited upstream performance results below are historical
reference data, not measurements of the current Agentty build.

## Upstream performance reference

The inherited tty7 documentation reports the following five-run averages on an
Apple M1 Pro, macOS 26.3.1, using the same 155×40 grid. These results have not
been rerun for this Agentty development build.

| | **tty7** | Alacritty | Ghostty | Kitty |
|---|---:|---:|---:|---:|
| Plaintext I/O — 11 MB `cat` <sub>(lower is better)</sub> | **95 ms** | 239 ms | 179 ms | 185 ms |
| [DOOM-fire](https://github.com/const-void/DOOM-fire-zig) frame rate <sub>(higher is better)</sub> | **888 fps** | 485 fps | 552 fps | 617 fps |
| Cold-launch memory | 116 MB <sup>1</sup> | 105 MB | 128 MB | 130 MB |

<sub><sup>1</sup> GUI 105 MB plus the persistent server at 11 MB.</sub>

The methodology and a one-command reproduction live in
[`scripts/bench/`](https://github.com/l0ng-ai/tty7/tree/main/scripts/bench).

Three decisions account for most of it:

- **The PTY is read at device speed** and parsed in large batches, off the
  render path — so drawing never throttles reading.
- **The hot paths are lock-free.** A big `cat` never waits on the renderer.
- **The server buffers up to 16 MiB** ahead of the window before backpressure
  applies, which is enough that a flood finishes writing while the window is
  still catching up.
